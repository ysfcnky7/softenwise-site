## S70 | 07 — Güvenlik ve Yasal | Güvenlik Prosedürleri Uygulama İçin
S70.1| **Secrets Extraction:** Extract all hardcoded credentials, API keys, JWT secrets, connection strings, and private keys into `.env` files.
S70.2| **Git History Purging:** Sanitize Git history using `git filter-repo` or `BFG Repo-Cleaner` if any `.env` or secret was ever committed.
S70.3| **Environment Security:** Ensure `.env*`, `*.pem`, `*.key`, `*.keystore`, and `google-services.json` are strictly added to `.gitignore`.
S70.4| **Client-Side Secret Shielding:** Never store or expose private API keys (e.g., Stripe Secret Key, AWS Access Key, database credentials) inside Web or Mobile client-side code. Use dedicated backend proxy endpoints for external integrations.
S70.5| **Password Hashing:** Hash passwords using Argon2id or bcrypt (minimum work factor 12). Never use MD5, SHA-1, or plain SHA-256.
S70.6| **JWT Security & Rotation:** Use short-lived Access Tokens (e.g., 15 mins) and long-lived, single-use Refresh Tokens with automatic token rotation and revocation list in Redis.
S70.7| **Cookie Hardening:** Set cookies with `HttpOnly`, `Secure`, `SameSite=Strict`, and explicit `Domain`/`Path` attributes.
S70.8| **Rate Limiting & Brute-Force Protection:** Implement IP-based and user-based Rate Limiting (Redis Sliding Window or Token Bucket) on critical routes (`/login`, `/register`, `/forgot-password`, `/verify-otp`, `/reset-password`).
S70.9| **Multi-Factor Authentication (MFA/2FA):** Enforce TOTP / WebAuthn support for elevated actions and administrative accounts.
S70.10| **Account Lockout:** Temporarily lock accounts after N consecutive failed login attempts to prevent brute-force attacks.
S70.11| **Session Termination & Invalidation:** Invalidate server-side sessions instantly on logout, password change, or suspicious activity.
S70.12| **Account Deletion (GDPR/KVKK Compliance):** Ensure "Delete Account" permanently purges or anonymizes all user PII from Primary DB, Redis Caches, S3 Buckets, and 3rd-party analytics.
S70.13| **Server-Side Authorization (BOLA/IDOR):** Validate user ownership and resource context strictly on the backend API layer. Never trust client-provided IDs without verifying if `request.user.id == resource.owner_id`.
S70.14| **RBAC & ABAC:** Enforce Role-Based Access Control and Attribute-Based Access Control on administrative, financial, and management endpoints.
S70.15| **Private Storage & Storage ACLs:** Keep cloud buckets (AWS S3, Azure Blob) private by default. Access files via time-limited Signed URLs / Pre-signed GET-PUT operations.
S70.16| **Mass Assignment Protection:** Use DTOs (Data Transfer Objects) / White-listing on incoming requests to prevent model binding pollution (e.g., users setting `isAdmin = true`).
S70.17| **Strict Schema Validation:** Validate incoming request payloads, headers, query parameters, and route params using strict schemas (Zod, FluentValidation, Joi, Dantic). Reject extra/unknown properties.
S70.18| **SQL Injection & NoSQLi Protection:** Use Parameterized Queries or ORM (EF Core, Prisma, Dapper, TypeORM) exclusively. Prohibit raw dynamic string concatenation inside raw database queries.
S70.19| **XSS & Contextual Output Encoding:** Escape all user-generated content rendered in HTML/React DOM. Sanitize HTML input with DOMPurify if HTML rendering is mandatory.
S70.20| Enforce file extension whitelisting (never trust user file extensions).
S70.21| Validate file headers / magic bytes (e.g., check PNG signature `89 50 4E 47`).
S70.22| Enforce maximum file size limits on reverse proxy and app layers.
S70.23| Strip EXIF / GPS metadata from uploaded images.
S70.24| Store files using UUID-generated filenames outside the web root directory.
S70.25| **SSRF (Server-Side Request Forgery) Mitigation:** Validate and whitelist destination URLs before making outbound HTTP requests from the server. Block internal IP ranges (`127.0.0.1`, `10.0.0.0/8`, `192.168.0.0/16`, AWS IMDS `169.254.169.254`).
S70.26| **TLS & HTTPS Enforcement:** Enforce HTTPS strictly across all environments. Redirect HTTP traffic to HTTPS with HSTS (`Strict-Transport-Security: max-age=31536000; includeSubDomains; preload`).
S70.27| **Strict CORS Policy:** Lock down CORS policies. Disable wildcard origins (`*`) in production. Specify exact trusted domain origins, allowed headers, and HTTP methods.
S70.28| **HTTP Security Headers:** Inject essential headers on all responses:
S70.29| `Content-Security-Policy (CSP)`
S70.30| `X-Frame-Options: DENY` (Clickjacking protection)
S70.31| `X-Content-Type-Options: nosniff` (MIME-sniffing protection)
S70.32| `Referrer-Policy: strict-origin-when-cross-origin`
S70.33| `Permissions-Policy` (Restrict camera, microphone, geolocation APIs)
S70.34| **Webhook Signature Verification:** Validate incoming webhooks (Stripe, GitHub, payment gateways) using HMAC-SHA256 signatures before processing payloads.
S70.35| **Reverse Proxy & WAF:** Place backend services behind a Web Application Firewall (Cloudflare, AWS WAF) to filter DDoS, bad bots, and malicious payloads.
S70.36| **Production Error Masking:** Suppress detailed stack traces, internal paths, database exceptions, and framework details in production. Return generic standardized error responses (e.g., `{"error": "An unexpected error occurred"}`).
S70.37| **Log Sanitization & PII Filtering:** Mask or scrub sensitive data (Passwords, Credit Card numbers, JWTs, Access Tokens, Social Security numbers) before writing to application logs.
S70.38| **Audit Logging:** Record security events (failed logins, privilege escalation, password resets, key rotation, admin actions) with timestamps, IP addresses, and user IDs.
S70.39| **Billing & Cost Monitoring Alerts:** Configure automated cost threshold alerts on AWS, GCP, Cloudflare, and Sentry to detect and mitigate L7 DDoS and resource exhaustion attacks.
S70.40| **Dependency Vulnerability Audits:** Run automated dependency vulnerability scans (`npm audit`, `dotnet list package --vulnerable`, Snyk, Trivy) and eliminate critical/high vulnerabilities.
S70.41| **Secure Local Storage:** Never store sensitive user tokens, JWTs, or encryption keys in `AsyncStorage`, `localStorage`, or unencrypted SQLite databases. Use `expo-secure-store`, iOS Keychain, or Android EncryptedSharedPreferences / Keystore.
S70.42| **Certificate Pinning (SSL Pinning):** Implement SSL/TLS Certificate Pinning on mobile network layers to prevent Man-in-the-Middle (MitM) interception on untrusted networks (public Wi-Fi).
S70.43| **Jailbreak / Root Detection:** Detect compromised mobile operating systems (Jailbroken iOS / Rooted Android) and block execution or disable sensitive features.
S70.44| **Code Obfuscation & Binary Protection:** Obfuscate JS bundles, enable ProGuard/R8 for Android, and strip debugging symbols before generating App Store / Google Play release builds.
S70.45| **Screen Capture & Overlay Protection:** Disable screenshot/screen recording capabilities on sensitive views (e.g., payment, personal identity, credentials screens).
S70.46| **Biometric Authentication:** Secure local app opening with FaceID / TouchID / Biometric Prompt integrated with native hardware keystores.
S70.47| **Automated Static Analysis (SAST):** Run SAST tools (SonarQube, Semgrep) to identify code-level security issues during CI/CD builds.
S70.48| **Dynamic Application Security Testing (DAST):** Test live APIs and web surfaces with tools like OWASP ZAP or Burp Suite.
S70.49| Saldırı PoC / exploit / payload YAZMA. Yalnızca kodda koruma var mı bak: SQLi parametre, IDOR yetki, auth bypass, tehlikeli yükleme, XSS kaçış. Yoksa düzelt. Kanıt: dosya yolu.
S70.50| SQLi: ham string birleştirme var mı kontrol et; varsa parameterized/ORM yap. Payload/exploit yazma.
S70.51| IDOR: istemci ID'sine güvenilen uç var mı bak; sunucuda sahiplik kontrolü ekle. Başkasının kaydını çekme denemesi/PoC yok.
S70.52| Auth bypass: korumasız admin/ödeme ucu var mı bak; düzelt. Token sahtekarlığı denemesi yazma.
S70.53| Yükleme varsa uzantı + magic byte + boyut; kabuk yükleme denemesi yazma.
S70.54| XSS: kullanıcı metni kaçışsız render ediliyor mu bak; düzelt. Script enjekte etme.
